# ADR 0006: 采用 mise-en-place 作为全局统一运行时与工具链管理器

## 状态

已接受 (Accepted)

## 背景 (Context)

在 Homelab 混合节点与跨平台开发环境的演进中，传统依赖安装模式暴露出严重的工程缺陷：

1. **宿主机污染**：大量使用 `npm install -g`、`pip install --user` 或 `brew` 导致系统全局环境状态漂移，甚至引发依赖地狱。
2. **多版本冲突**：不同项目需要不同的 Node.js 或 Python 版本，使用 `nvm`、`pyenv` 等独立工具管理时，Shim 层混乱，终端启动性能受到严重拖累。
3. **AI 生成代码的不可控性**：大语言模型习惯性地给出 `sudo apt-get` 或 `pip install` 的“快餐式”解决方案，这与 PEOS (个人工程操作系统) 追求的高度隔离与确定性理念背道而驰。

## 决策 (Decision)

我们决定在 PEOS 的全域基础设施中，全面采用 `mise-en-place` 接管运行时拓扑：

1. **确立单一事实来源**：所有项目的运行时环境与开发工具必须通过 `.mise.toml` 进行声明式定义。
2. **全面封杀全局安装指令**：在 `mise_runtime_topology` 上下文中设定安全红线，禁止 AI 在 `ai-kit-maintainer` 和 `ansible-engineer` 角色下生成破坏性的全局系统包安装脚本。
3. **指定后端引擎**：强制规定 Python 工具包必须通过 `uv` 引擎分发（如 `"uv:black" = "latest"`），以获取极致的安装速度与严格的虚拟化隔离。

## 影响 (Consequences)

- **正面影响**：
  - 实现了 100% 的项目级运行时环境隔离，彻底消灭“在我的机器上能跑”的问题。
  - 大幅提升了大模型生成的 Ansible 脚本及环境配置指南的规范性与系统安全性。
- **负面影响**：
  - 提高了编写临时脚本的心智门槛。所有原本一句话解决的依赖安装，现在都必须抽象为 `.mise.toml` 配置修改或 `mise run` 任务。
