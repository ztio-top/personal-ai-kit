### 4. ADR (架构决策记录)

**状态**: 已采纳 (Accepted)
**决策标题**: ADR-007: 建立基于 SSOT 别名映射与双模演进的元数据标签治理架构

#### Context (背景)

随着知识库文档规模的扩大，人工书写与大模型自动打标均不可避免地带来了标签漂移、同义词泛化（如 `k8s` vs `kubernetes`）以及大模型“配额填充（Quota-Padding）”现象（为了凑满数量盲目附加无关的宏观泛概念标签）。原有的单向注入工具已无法满足长期维护中对 SSOT（唯一真实数据源）纯净度与灵活性的双重诉求。

#### Decision (决策)

我们在 `peos-doctor` 治理工具链中引入了一套完整的离线合规审计与清洗系统：

1. **别名归一化层**：在 `tags.yaml` 中引入 `aliases` 映射表，确保在审计时能够确定性地将历史及大模型产生的常见别名静默转为规范全称。
2. **双模演进治理**：
   - **严格净化模式 (`--audit --fix`)**：阻断未注册标签污染，保持核心字典的高纯度。
   - **演进同步模式 (`--audit --fix --sync-tags`)**：构建由人工确认并触发的 SSOT 动态生长闭环。
3. **提示词反泛化收敛**：在 LLM 打标 Prompt 中显式声明“宁缺毋滥”与反对凑数的反向约束，将速查手册等文档的标签颗粒度严格收敛至 1-3 个核心实体。

#### Consequences (影响)

- **正面影响**：彻底解决了标签碎片化和同义词泛滥问题；大幅提升了大模型自动打标的精准度，避免了噪声标签对未来 RAG 检索带来的干扰。
- **负面影响**：引入了显式的离线治理维护成本（需要架构师定期执行合规审计并决定新标签的去留）。
