# ADR 0003: 采用 AI 驱动的语义打标增强治理引擎

## 状态

已接受 (Accepted)

## 背景

在扁平化领域目录的 PEOS 拓扑中，精准的 Tag 是驱动 RAG 检索引擎高信噪比的核心依赖。人工打标存在遗漏和心智摩擦力，而基于正则表达式的传统自动化打标存在“上下文致盲”问题（例如：文档中写“放弃使用 K3s”，正则仍会愚蠢地分配 `k3s` 标签，严重污染检索池）。

## 决策

我们在 `peos-doctor` 治理引擎中引入智能打标流水线（通过 `--auto-tag` 唤起）：

1. **本地大语言模型介入**：挂载 Ollama 引擎，将前 1000 个字符发送给大语言模型进行语义级阅读理解。
2. **强制 JSON 约束**：要求模型仅能输出合法 JSON 数组，温度设为 `0.0`。
3. **闭源字典硬隔离**：模型推理出的标签在写入文件前，必须经由 Python 代码层与 `9-Metadata/tags.yaml` 求交集。即使模型产生幻觉伪造标签，也会被物理层丢弃。

## 影响 (Consequences)

- **正面**：实现了无需人类干预的高质量全量元数据修复。将“自动化脚本”升级为了具备“阅读理解能力”的智能体。空标签 `tags: []` 现象现在意味着字典缺失，而不是扫描漏报，起到了反向驱动词库演进的作用。
- **负面**：批处理修复的速度大幅降低，强依赖于本地 GPU 的推理速度。为此我们将该功能设计为 `--auto-tag` 可选参数 (Opt-in)，且剥离了超时与异常，确保网络或 GPU 服务离线时不阻塞正常的基线治理工作。
