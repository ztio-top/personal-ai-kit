### 4. ADR (架构决策记录)

**状态**: 已采纳 (Accepted)
**决策标题**: ADR-008: 采用原生 JSON 模式与结构化 CoT 推理应对中型大模型的指令遵循衰减

#### Context (背景)

在使用 14B 级别大语言模型（如 Qwen2.5:14b）执行 `peos-doctor` 的自动化打标任务时，暴露出两个严重的工程缺陷：

1. **格式幻觉**：模型极易忽视“仅输出 JSON”的指令，在结果中掺杂 Markdown 代码块或分析性口水话，导致 JSON 解析器崩溃。
2. **局部示例污染 (Local Example Pollution)**：当长文档中包含大量代码示例（如讲解 AI 插件时大篇幅粘贴 Java 代码），模型会被示例的高频词汇“劫持注意力”，无视“全局主旨锚定”的负向提示词，给出严重失真的标签。

#### Decision (决策)

为确保元数据治理流水线的绝对确定性，我们对底层 LLM 通信架构与 Prompt 范式进行了三项重大重构：

1. **API 层强制锁死**：激活 Ollama 原生的 `"format": "json"` 参数，并在第一顺位注入硬性 System Prompt，剥夺模型输出非结构化文本的自由。
2. **引入 JSON-based CoT (思维链)**：修改输出契约，强制模型在输出 `"tags"` 数组前，必须先输出 `"semantic_analysis"` 或 `"audit_log"` 字段。通过强迫模型先自我剖析“文档核心主旨”与“排除了哪些局部干扰示例”，从而在内部生成阶段手动修正其注意力权重。
3. **引入本体映射 (Ontology Mapping)**：增加显式的“降级抽象”规则，指导模型在遇到 SSOT 字典未覆盖的微观实体（如具体的 CLI 命令）时，自动映射到宏观技术域，杜绝空标签错杀。

#### Consequences (影响)

- **正面影响**：彻底消灭了正则解析失败的异常；打标精准度产生质的飞跃，成功免疫长文本中的代码示例干扰；极大地提升了终端日志的可观测性。
- **负面影响**：由于 CoT 机制强制模型输出额外的数百个 Tokens 的分析文本，导致单篇文档的推理耗时略有增加（约增加 1-2 秒），但在离线审计场景下该性能损耗完全可以接受。
